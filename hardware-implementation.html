MVP-1 · HARDWARE IMPLEMENTATION

From gesture to physical output.

This page documents the bounded university mini-project demonstrator: gesture text from the browser MVP, wireless text transfer to a microcontroller and OLED, and a separate audio-amplifier path.

SYSTEM BOUNDARY
One platform, separate demonstrator

This is a hardware implementation record inside SIGNALINK MVP-1. It does not expose private development repositories or claim that planned hardware is already verified.

SYSTEM ARCHITECTURE

Two output paths

  • Text path: Supported gesture → browser-recognised text → BLE UART → ATmega328P → SSD1306 OLED.
  • Audio path: Browser text-to-speech → phone audio output → analogue audio cable → LM386 amplifier → speaker.
  • NFC role: Opens the website URL only; it does not carry the recognised text or audio.

Current browser gesture labels are HELLO, STOP and YES. Other messages should not be presented as recognised gestures unless implemented and tested.

HARDWARE STACK

Prototype components

  • Controller: ATmega328P-PU standalone microcontroller, planned for 3.3 V / 8 MHz operation.
  • Wireless link: HM-10-compatible BLE UART module; exact module and UUIDs must be verified.
  • Display: SSD1306 0.96-inch, 128 × 64 I²C OLED.
  • Audio: LM386 amplifier, audio input connection, speaker and separate amplifier supply.
  • Programming and support: USBasp ISP programmer, regulated supply, decoupling and wiring.

ENCLOSURE / 3D PRINTING

OLED-first, full-hardware-fit case

The OLED determines the visible display opening, but the outer case must fit the whole assembled electronics—not just the screen.

  • Measure the actual OLED PCB width, height, thickness and active display area; design the bezel/opening around the visible area.
  • Measure the controller/BLE board footprint, component height, wiring bends and mounting-hole positions.
  • Reserve space for the selected power source, switch and any programming/access connector that must remain reachable.
  • Add internal standoffs, screw clearance, wall thickness and print tolerance only after measuring the parts.
  • Print a small fit-check or front-panel prototype before the final enclosure.

Dimension status: Not frozen yet. “0.96-inch OLED” describes the display class, not the full module or enclosure.

VERIFICATION CHECKLIST

Evidence before calling it complete

  • BLE connection succeeds with the actual module and matching service/characteristic UUIDs.
  • A test message reaches the microcontroller and appears correctly on the OLED.
  • Phone audio is heard clearly through the LM386 and speaker.
  • Supply voltages, common ground, logic-level compatibility and wiring are checked.
  • Enclosure measurements, internal fit and OLED alignment are documented.
